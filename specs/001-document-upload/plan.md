# Implementation Plan: Document Upload and Management

**Branch**: `001-document-upload` | **Date**: 2026-05-22 | **Spec**: [`specs/001-document-upload/spec.md`](specs/001-document-upload/spec.md)
**Input**: Feature specification from `/specs/001-document-upload/spec.md`

## Summary

Implement document upload, organization, sharing, and management capabilities for the ContosoDashboard Blazor Server application. The feature enables employees to upload work-related documents (up to 25 MB, PDF/Office/images), organize them by category and project, share with team members, and access them through My Documents, Project Documents, and Shared with Me views. The system will use local filesystem storage with GUID-based filenames, EF Core for metadata persistence, and integrate with existing notification and authentication systems.

## Technical Context

**Language/Version**: C# / .NET 8.0  
**Primary Dependencies**: ASP.NET Core 8.0, Blazor Server, Entity Framework Core 8.0, Bootstrap 5.3, Bootstrap Icons  
**Storage**: SQL Server LocalDB (metadata), local filesystem (file storage outside wwwroot)  
**Testing**: xUnit, Moq, Microsoft.AspNetCore.Mvc.Testing  
**Target Platform**: Windows (Blazor Server, offline-capable)  
**Project Type**: Single web application (Blazor Server)  
**Performance Goals**: 100 users, 10,000 documents, 50 concurrent uploads; page loads < 2 seconds for up to 500 documents per user  
**Constraints**: Integer DocumentId (not GUID), text Category (not enum), offline-first operation, cookie-based auth, no external APIs or cloud services  
**Scale/Scope**: Small-scale training system — 100 users, 10,000 documents, 50 concurrent uploads

## Constitution Check

### Security-First
- [x] **IDOR Protection**: Every document access MUST validate user ownership or sharing permissions at the service layer (FR-028, FR-041)
- [x] **Authorization**: Service-level checks for upload, download, share, delete, edit operations (FR-040)
- [x] **File Storage**: Files stored outside web-accessible directories with GUID-based filenames (FR-011)
- [x] **Input Validation**: File type whitelist, size limit (25 MB), title required (FR-002, FR-003, FR-005)
- [x] **Virus Scanning**: Simulated scanner interface for demonstration (FR-010)

### Clean Architecture
- [x] **Models**: Document, DocumentShare, DocumentAuditLog entities only (no business logic)
- [x] **Services**: DocumentService, IFileStorageService encapsulate all business rules
- [x] **Data**: ApplicationDbContext extended with DbSet properties only
- [x] **Pages**: Blazor components delegate to services, never access DB directly
- [x] **Interfaces**: IFileStorageService abstraction for filesystem operations

### Offline-First
- [x] **No External APIs**: Local filesystem storage, LocalDB, mock authentication
- [x] **Abstraction Boundaries**: IFileStorageService allows future cloud migration
- [x] **No CDN Dependencies**: Bootstrap bundled locally

### Test-First (NON-NEGOTIABLE)
- [x] **Service Tests**: Authorization logic, file operations, sharing workflows
- [x] **Integration Tests**: Full request path: page → service → data context
- [x] **Unit Tests**: Model validation, file type checking, size limits
- [x] **Negative Cases**: Unauthorized access, invalid files, disk full scenarios
